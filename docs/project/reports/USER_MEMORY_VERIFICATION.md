# 使用者記憶第一版驗收清單

## 使用方式

- 完成 SQLite 記憶功能後依序驗證。
- 每一項都必須能觀察到結果；不能只以「程式沒有拋出例外」判定通過。
- 發現問題時記錄輸入、實際結果及相關 log，但不得抄錄敏感資料。

## 1. 啟動與資料庫

- [ ] 第一次啟動時可自動建立 `agent_memory.db` 與必要 schema。
- [ ] 再次啟動不會重複建立資料表或破壞既有資料。
- [ ] Migration 可重複檢查，已套用的版本不會再次執行。
- [ ] 目前使用者固定識別為 `local-default`。
- [ ] 資料庫無 TurnId、聲紋、Profile 歷史等第一版未使用的結構。

## 2. CMD 與 STT 流程

- [ ] CMD 輸入會進入 Router、回答及背景記憶流程。
- [ ] STT 輸入經文字整理後，進入與 CMD 相同的 Router、回答及背景記憶流程。
- [ ] CMD 與 STT 寫入相同的 `local-default` Profile。
- [ ] STT 辨識失敗或空字串時不建立空白訊息或記憶。

## 3. 最近對話

- [ ] 當輪回答可以取得最近兩輪對話。
- [ ] 代名詞或省略語句可延續前文，例如「我週末要去台南」之後詢問「那邊天氣如何」。
- [ ] 第三輪以前的原始訊息不會無限制塞入 Prompt。
- [ ] Context 接近模型 token 上限時會裁切或摘要，不會造成推論超過 1024 tokens。
- [ ] 新 Session 不會錯誤帶入上一個 Session 的短期對話。

## 4. 一般資料保存

- [ ] 「我喜歡科幻電影」可形成記憶候選並寫入 Profile 或 `MemoryItems`。
- [ ] 相同資料重複出現時不會建立重複記憶。
- [ ] 「我也喜歡懸疑電影」會與既有興趣合併。
- [ ] 程式重新啟動後仍能讀取已保存的資料。
- [ ] Agent 可在相關話題中合理使用記憶，不會在無關回答中強行提及。

## 5. 更新與衝突

- [ ] 「我已經不住台北，現在住台中」會以台中取代台北。
- [ ] 明確更正後不會繼續使用舊資料回答。
- [ ] 「最近都在餐廳幫忙」不會在缺乏明確說明時把既有職業改成餐飲業。
- [ ] 不明確或互相衝突的候選資料會被忽略。
- [ ] 只有衝突內容會影響目前回答時，Agent 才主動詢問使用者。

## 6. 敏感與禁止資料

- [ ] 健康資料在保存前會取得明確確認。
- [ ] 財富資料在保存前會取得明確確認。
- [ ] 使用者拒絕後不會寫入 Profile 或 `MemoryItems`。
- [ ] 第一版同時只保留一筆待確認變更；程式重啟後可安全捨棄。
- [ ] 密碼不會寫入 SQLite。
- [ ] 身分證號、驗證碼與 API／加密金鑰不會寫入 SQLite。
- [ ] 禁止資料不會以明文出現在一般 log。
- [ ] LLM 建議保存禁止資料時，C# `MemoryPolicy` 仍會拒絕。

## 7. 忘記與清除

- [ ] 使用者要求忘記某項資料時，對應 Profile 欄位與 `MemoryItems` 會被刪除。
- [ ] 能明確定位的相關對話訊息會一併刪除。
- [ ] 無法可靠定位時不會用模糊比對大量刪除資料。
- [ ] 無法定位時可選擇清除目前 Session 或全部對話。
- [ ] 超過 30 天的對話訊息會在程式啟動清理時移除。
- [ ] 清除訊息後，空的 Session 可以一併移除。

## 8. 背景處理與穩定性

- [ ] 回答或 TTS 會先輸出，不等待記憶分析完成。
- [ ] `MemoryJob` 包含 UserId、Input、Route、Response 與 ReviewHint 的完整快照。
- [ ] 下一輪輸入開始後，上一輪背景工作不會把資料寫到錯誤使用者或錯誤內容。
- [ ] 記憶分析或 SQLite 寫入失敗不會中止主程式。
- [ ] 關閉程式時 Memory Worker 能正常停止，不產生未處理例外。
- [ ] SQLite 暫時鎖定或寫入失敗時有錯誤紀錄，但 log 不包含敏感原文。

## 9. Agent 個性邊界

- [ ] 使用者 Profile 與 `agent_profile.json` 分開保存。
- [ ] 使用者偏好不會直接改寫全域 Agent 個性。

Agent 主動修改個性、確認流程與檔案備份不屬於本次 SQLite 記憶第一版的完成門檻。

## 10. 現有功能回歸

- [ ] `answer`、`chat`、`support`、`tool`、`clarify` 與 `retrieve` 路由仍符合 Parser 規格。
- [ ] 現有本地工具仍可正常執行。
- [ ] CMD 與 STT 的輸入排序仍由既有 Channel 與 `GlobalStateService` 控制。
- [ ] TTS 仍可播放一般回答與工具結果。
- [ ] OGA 與 ONNX 資源在程式關閉時正常釋放。

## 完成判定

以下條件全部成立，才可將使用者記憶第一版標示為完成：

- 本清單沒有未處理的失敗項目。
- 自動化測試、整合測試或人工驗證結果已留下可追蹤紀錄。
- 實際資料庫 schema 與[使用者記憶設計](USER_MEMORY_DESIGN.md)一致。
- 沒有因方便實作而提前加入延後項目。
