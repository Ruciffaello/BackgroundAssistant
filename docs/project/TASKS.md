## 下一步

### FEAT-002 實作使用者記憶第一版

- 說明：依精簡版設計加入固定使用者識別、Profile、最近兩輪對話及不阻塞回答的背景記憶處理。
- 完成條件：CMD 與 STT 共用記憶流程；一般資料可安全保存，敏感資料先確認，禁止資料不寫入；重啟後可讀回已確認資料。
- 範圍限制：不實作 TurnId、聲紋、RAG、Profile Tool、細分 Profile 資料表或版本歷史。
- 規格：[使用者記憶設計（精簡版 V1）](reports/USER_MEMORY_DESIGN.md)。
- 驗收：[使用者記憶第一版驗收清單](reports/USER_MEMORY_VERIFICATION.md)。

### TECH-001 建立可重複驗證的開發流程

- 說明：目前沒有正式測試專案與自動建置流程。
- 完成條件：專案具備可執行的自動建置與基礎測試，結果可被重複驗證。

### TECH-002 完成本地工具實作與行為校正

- 說明：部分本地工具仍為模擬或未完成實作，部分行為需要依需求重新確認。
- 完成條件：目標工具的實際行為、錯誤處理與驗收方式均已確認並通過測試。

### TECH-003 整理設定與秘密資料管理

- 說明：模型路徑及部分執行參數仍寫在程式中，敏感設定需要移出受 Git 追蹤的檔案。
- 完成條件：環境相關設定可由外部提供，Git 追蹤內容不含有效秘密資料。

### FEAT-001 加入語音喚醒機制

- 說明：加入喚醒詞，降低非指令語音進入處理流程的機會。
- 完成條件：喚醒條件、資源限制與語音流程整合均通過驗證。

### TECH-004 設計 DLL 工具插件機制

- 說明：讓產品可透過 DLL 插件加入特定功能，並納入統一工具目錄。
- 完成條件：定義插件契約、manifest、載入生命週期、安全、錯誤隔離及版本相容規則。
